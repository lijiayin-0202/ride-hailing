## 7. 校验模式：单轮一次性校验（仅探测、不自动修复）

> 本节约束的是**校验的执行方式**，适用于「扫描项目 + 自检规则文档」的单轮探测校验。

### 7.1 校验目标

只执行**一轮**扫描探测。目标仅为：**扫描流程正常跑通、无脚本/规则报错**。

### 7.2 执行约束

1. **只执行一轮完整检查**：**不自动修复任何违规项、不生成修改 patch、不进入多轮迭代整改**。
2. **全部既定检查项照常执行**（扫描范围见 §7.6）：环境变量清单表格残留、裸 `os.Getenv` / `os.LookupEnv`、全局裸 DB / 裸 kafka client、**Kratos 分层反向依赖（C8，见 §7.5）**、wire 依赖注入、proto 规范、敏感配置泄露等。
3. **只输出标准报告**：无论检出多少污染/违规，报告固定为三部分——① 变更条目；② 污染标记检查；③ 残留位置清单。
4. **报告末尾强制追加标注**：

   ```
   【单轮探测校验完成，扫描流程无异常。本次不自动修复问题，如需整改请单独下发修改指令】
   ```

5. **判定标准**：**扫描流程完整跑完、无内部脚本报错 = 本轮校验成功**；业务违规项仅罗列，**不计入校验失败**。

### 7.3 额外约定：仅流程崩溃才用报错模板

仅当执行过程中发生**扫描流程内部报错、命令异常、规则解析失败**时：停止常规报告输出，改输出 §7.4 模板。

> 检出业务违规（裸 `os.Getenv`、分层违规等）属于**正常探测结果**，**不使用**报错模板，照常输出标准报告 + §7.2 第 4 条末尾标注。

### 7.5 C8 · Kratos 分层反向依赖检查

- **规则来源**：`agent/01-stack-structure.md` §4 分层职责（禁止跨层反向依赖）。
- **允许调用方向**：`api` → `internal/service` → `internal/biz` → `internal/data`。
- **禁止 import 清单**：

| # | 禁止的 import | 说明 |
|---|---------------|------|
| 1 | **biz 层 import service** | 领域层不得反向依赖编排层 |
| 2 | **data 层 import biz** | 数据层不得反向依赖领域层 |
| 3 | **service 层直接 import data** | 绕过 biz 直接操作数据 |
| 4 | **data / biz / service 反向依赖上层** | 任何下层 import 上层包均为违规 |

- **扫描方式**：检索 `.go` 文件的 `import` 导入路径，按文件所在层（`api` / `service` / `biz` / `data`）比对上表，识别跨层反向引用。
- **判定**：命中即为违规 → 收集**文件位置**与**导入路径**，录入残留位置清单；**仅探测上报，不阻断流程、不自动修复**。

### 7.6 全局扫描过滤（排除规则文档，避免假阳性）

- **排除目录**：`.agent/**/*`——**所有 C1~C8 检查项**在检索时一律跳过该目录下的全部文件。
- **扫描对象**：只扫描**业务代码**（`.go`、配置与业务资源）；**不再扫描规则文档、流程 md 文档**。
- **目的**：避免文档内的示例代码、关键词（如 `os.Getenv`、`wire`、`proto` 等规则文本）产生大量假阳性命中。
- **判定口径**：**只收集业务代码中的违规**；文档内部示例**不计入**污染清单/残留位置清单；检出违规只上报，不阻断校验流程、不自动修复。
- **生效范围**：C1 环境变量清单表格残留、C2 裸 `os.Getenv` / `os.LookupEnv`、C3 全局裸 DB / kafka client、C8 Kratos 分层反向依赖、C4 wire 规范、C5 proto 规范、敏感配置泄露——全部适用。
