# 00 · agent 目录元规则

> 隶属 AGENT.MD v1.2.0 · 更新日期 2026-10-26

## 1. 目录定位

本目录是项目规则的唯一存放处，"一文件一主题"。总纲 `AGENT.MD`（仓库根）回答"是什么、红线是什么"；本目录回答"具体怎么做"。具体规则见 01~08。

> **文档分类（改文档前必读）**：`AGENT.MD §5 提交规范`、`§6 Git 提交流程`、`§9 测试五道关` 为团队通用规范；`01` 技术栈与目录、`02` 数据与契约、`04` 部署配置、`08` 命令生成与开发流程为**本仓库专属**（Kratos + Blades，详见 `01 §1`）。

## 3. 写作规则

1. 每条必须可执行：写"必须/禁止/命令/路径"，不写"尽量/建议/可以考虑"。
2. 不复制 `AGENT.MD` 已有内容：只引用章节号（如 `AGENT.MD §5`）。
3. 换技术栈才改本目录；改任何文件须在文件头更新版本号与日期。
4. 引用格式：`agent/03 §5`，**不要引用行号**。
5. 不改其他文件的职责范围；发现规则缺失 → 提案新增章节，不塞进别的文件。

## 4. 效力顺序

`AGENT.MD` > 01 > 03 > 08 > 02 > 04 > 05 > 07 > 06。冲突时以排位靠前为准；都不覆盖 → 群里问负责人，不得自行放宽。

## 5. 修改流程

1. 群内提案（改什么、为什么、影响哪些文件）。
2. 负责人确认后开 `docs/T-xxx-agent-rules` 分支修改，PR 合并。
3. 同步更新 `AGENT.MD` 版本号与本文件头日期。

## 6. AI 约定

1. 开工顺序：`AGENT.MD` → 本文件 → `01` → `02` → `03` → `08`（命令与流程），再读目标目录代码。
2. 结论可验证：每项交付说明"怎么验证、验证结果"。
3. 与规则冲突时：停手 + 群里问，不得自行放宽或猜。
4. 改动前先 `git status` 确认分支正确（业务分支 or 白名单框架改动）。
