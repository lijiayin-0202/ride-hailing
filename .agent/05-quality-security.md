# 05 · 测试规范、安全与 AI 红线

> 隶属 AGENT.MD v1.3.0 · 更新日期 2026-10-27

## 1. 测试规范

五道关（①真实库 ②本地能跑通 ③Apipost 测通 ④浏览器无报错 ⑤测试流一轮跑通）的**权威定义见 `AGENT.MD §9`**；本节补充本框架落地细节。

| 项 | 要求 |
|----|------|
| 单元测试 | biz 层领域规则必须有用例，`make test` 输出覆盖率，核心域 ≥60% |
| 集成测试 | data 层连真实测试 PostgreSQL + 真实 Redis；数据 `test_` 前缀，`t.Cleanup` 清理 |
| RAG 检索测试 | 真实 embedding 用例：插入 → topK 检索 → 断言相似度序；换模型/维度后回归 |
| 接口工具（Apipost） | 三类用例：正常 / 参数校验失败 / 未登录；**SSE 流式验证事件序列**（TEXT→TOOL_CALL→TOOL_RESULT→DONE，异常路径 ERROR）；gRPC 用客户端脚本实测 |
| 浏览器验证 | 前端会话页 Chrome 打开：流式输出渲染、中断恢复、Console/Network 无报错 |
| 测试流一轮跑通 | 执行一轮，链路跑通、无报错即可；开发者可按需自行多轮回归，**多轮不再是强制门禁、不作 PR 阻断**（定义见 `AGENT.MD §9`） |
| Kafka 测试 | 生产后消费端能收到；`event_id` 幂等去重有效；失败进入重试/DLQ 路径各验一遍 |
| 治理验证 | 超时、限流（按 agent_id）、熔断触发路径各实测一次 |

## 2. 数据安全（硬要求）

1. 租户隔离：所有读写带租户条件校验（biz 层），**禁止跨租户读取 Agent 配置与会话**。
2. 密钥与模型原始报错**禁止透传调用方**：内部记完整堆栈，对外返回简化 message + 业务 code。
3. 日志禁止打印：模型密钥、用户对话原文（确需留痕按脱敏规范）、SQL 参数明文。
4. Prompt 注入防护：输入过滤/敏感词 Middleware 统一挂 blades 层；工具调用参数白名单校验。
5. 会话 Memory（Redis）设 TTL，过期即失效；Agent 关键执行步骤落审计日志。
6. 依赖漏洞：`govulncheck` 高危必须处理或书面说明不可利用。

## 3. AI 行为红线（任一命中即阻断提交）

1. **不动框架**：不换框架、不重构 Makefile/buf/wire/目录分层、不私自升级大版本。
2. **不自造接口**：字段名、事件类型、错误码必须与 proto / 接口文档一致，不猜测。
3. **不手改生成物**：`*.pb.go`、`wire_gen.go`、`buf.lock` 一律重新生成。
4. **不散装调用模型 API**：模型/工具/Memory 必须经 `internal/blades` 封装。
5. **不擅自加依赖**、不新开顶层目录（判定见 `agent/01 §8`）。
6. **不伪造验证**：必须真实执行构建/测试/浏览器验证，如实回报失败与未测项。
7. **不吞错误**：流式异常必须推送 ERROR 事件并关流；消费失败必须有重试/DLQ 兜底。
8. **不提交敏感信息**：`.env`、模型密钥、真实用户对话、日志文件、`bin/`。

## 4. 代码质量底线

- 函数 ≤ 80 行、单文件建议 ≤ 500 行，超限拆分并在 PR 说明。
- 错误处理：业务错误统一 kratos error 带业务 code；data 层错误必须转换后再上抛。
- context 全链路透传，禁止 `context.Background()` 出现在业务代码。
- goroutine 必须 `recover` 与超时控制；SSE 心跳保活、超时自动断开。
- 注释规则按 `AGENT.MD §7.2` 执行；生成代码注释由工具生成，不手改。
