# 07 · 共享文件冲突规避与契约先行

> 隶属 AGENT.MD v1.2.0 · 更新日期 2026-10-26

## 1. 共享文件清单（改前先在群里说，改时只加不改他人段）

| 文件 | 归属维护人 | 冲突点 | 规避方式 |
|------|-----------|--------|----------|
| `api/agent/v1/agent.proto` | 接口归属人 | 并发加 rpc/message | 字段号只追加；新增域独立 proto 文件 |
| `internal/conf/conf.proto` | 负责人 | 配置结构变更 | 新配置先提案，字段号只追加 |
| `internal/server/http.go` / `grpc.go` | 负责人 | 服务注册 TODO 处 | 每个服务注册独立成行 + 注释任务号 |
| ProviderSet（biz/data/service） | 负责人 | 并发登记 wire Provider | 追加一行一处，PR 尽快合 |
| `agent/02 §4` topic 表 | 首个引入者 | topic 语义冲突 | 新 topic 先查表再群内确认 |
| `go.mod` / `go.sum` | 负责人 | 依赖版本冲突 | 依赖变更必须提案，禁止随手 tidy 夹带 |
| `configs/config.yaml` | 负责人 | 配置段并发追加 | 每人只追加自己的段，注释任务号 |

## 2. 契约先行顺序（谁先谁后）

```
① 数据字典/接口文档（飞书） → ② proto / 表结构 → ③ 命令生成(make api) → ④ 实现 → ⑤ 调用方接入
```

- 改 proto 前先在群里同步影响面（哪些调用方、哪些字段）；**禁止先写实现后补契约**。
- Kafka：先更新 `agent/02 §2` 表并群内确认，再写生产/消费代码。
- 库对象变更：迁移脚本先行，代码随后同步。

## 3. 状态与枚举（单一来源）

- SSE 事件类型（`TEXT / TOOL_CALL / TOOL_RESULT / DONE / ERROR`）：唯一定义在 `agent.proto` 枚举，代码只引用不另造。
- 业务错误码：集中定义在 `pkg/` 常量包，跨模块复用同一号段规则。
- 会话/Agent 状态枚举：唯一定义在 biz 层常量；变更须群内同步。

## 4. 分支寿命

- feature 分支存活 ≤ 5 个工作日；超期必须 rebase 最新 master 并在 PR 说明。
- 每 1~2 天 rebase 一次（冲突处理按 `agent/03 §5`），避免大冲突积压。
- 合并后立即删除分支；禁止复用已合并分支继续开发。

## 5. 冲突升级路径

两人自行解决 → 找文件归属人 → 仍定不了找负责人裁决 → 裁决结论若涉及规则修改，走 `agent/00 §5` 修订流程沉淀进文档。
