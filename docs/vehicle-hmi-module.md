# 模块四：车辆端与车内 HMI 交互

## 范围

- T0：车辆指令拉取、ACK、执行结果；乘客上车校验；车辆位置、状态和遥测上报。
- T1：车辆故障、远程协助、HMI 聚合视图。
- T2：媒体元数据登记，不包含视频存储和实时视频链路。

## 状态与幂等

车辆指令状态遵循数据字典：`0 待发送 -> 1 已发送 -> 2 已确认 -> 3 成功 / 4 失败`。

- `GET /api/v1/vehicle/commands/pending` 返回待下发和已发送未确认的指令，支持车辆离线重连后重新拉取。
- ACK 和执行结果采用条件更新，重复 ACK、重复成功结果或重复失败结果直接返回当前状态。
- 已发送指令不能跳过 ACK 直接上报结果，终态不能切换为另一终态。
- 指令按优先级数值升序、签发时间升序返回，紧急指令优先。

## 主要时序

1. 车辆拉取指令，服务把待发送指令标记为已发送。
2. 车辆收到指令后提交 ACK，状态进入已确认。
3. 车辆执行后提交结果，状态进入成功或失败。
4. 上车校验记录摘要和结果；成功记录与订单状态变更在同一事务内完成。
5. 遥测上报在同一事务内更新车辆快照，并写入位置、行程位置、状态变更和遥测日志。
6. 故障、远程协助和媒体记录写入数据字典已定义的业务表。

## 重试与乱序

- 客户端超时后使用相同业务编号重试，不生成新的指令编号或故障编号。
- ACK 前上报结果返回状态冲突；客户端重新拉取指令并补 ACK 后再提交结果。
- Kafka 发布失败时接口返回失败，由调用方重试；事件使用业务编号作为分区键。
- Kafka 事件必须由团队确认 topic 后再用于联调和生产环境。

## 联调前置

- PostgreSQL 已存在 `robotaxi` schema 及数据字典中的共享业务表。
- 车辆设备鉴权由网关完成，并把可信车辆身份传递给本服务；生产环境不得绕过网关直连接口。
- Kafka topic 和生产/消费组完成团队确认，且具备重试、DLQ 和消费幂等能力。
